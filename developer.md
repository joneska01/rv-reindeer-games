# Developer Reference — RV Reindeer Games

## Project Overview

Christmas-themed live scoring app for the RV (River Valley) annual holiday party. Couples compete in games each December. This app replaces a manual Excel spreadsheet.

**Live event flow:** Admin sets up teams/games in Setup Mode → runs the event in Live Mode (score entry, party fouls) → triggers podium reveal → shows Final Results. TV/projector is always on `/scoreboard`, which auto-polls and switches layout automatically.

## How to Add a New Game Type

1. No code change needed for standard manual games — admin creates via `/admin/setup` → Game Configuration → "Add from Scratch"
2. To add to the shared game library: insert a row in `game_library` via admin or seed data
3. For a completely new `score_source` type: update the `scoreSourceEnum` in `/db/schema.ts`, generate a migration, and add handling in `/lib/scoring.ts` → `computeGameRankings()`

## How Scoring Works

All scoring logic lives in `/lib/scoring.ts` as pure functions. No DB calls inside.

**Per-game flow:**
1. `computeGameRankings(game, scores, votes, teams)` → raw combined scores per team
   - Manual: sum or average round 1+2 (per `round_combine_method`), or just round 1
   - Voting (Costume Contest): sum vote points received (1st=10, 2nd=7, 3rd=5)
2. Sort by combined score (respecting `score_type: high_wins | low_wins`)
3. Assign placement points from the points table; tied teams share the higher place

**Overall leaderboard:**
- Sum placement points across ALL completed games
- Subtract party foul count
- Apply tie-breakers in order (see PRD §4.6)

**Points table:** 1st=30, 2nd=28, 3rd=26 ... 8th=16, 9th=14 ... 16th+=1

## How Polling Works

- `/scoreboard` page polls `GET /api/scoreboard` every 8 seconds
- `/vote` page polls `GET /api/votes` every 10 seconds
- Admin live leaderboard polls every 15 seconds
- `/api/scoreboard` is edge-cached for 5 seconds (handles 20-30 concurrent connections without DB saturation)
- Cache invalidated via `revalidateTag` on admin mutations

## Display Mode State Machine

`Year.display_mode` is the top-level TV switch. The `/scoreboard` page checks this on every poll.

```
scoreboard → (admin clicks "Reveal 3rd") → podium (show_third)
podium (show_third) → (admin clicks "Reveal 2nd") → podium (show_second)
podium (show_second) → (admin clicks "Reveal 1st") → podium (show_first)
podium (show_first) → (admin clicks "Show All") → podium (show_all)
podium (show_all) → (admin clicks "Show Final Results") → final_results
any state → (admin clicks "Reset Podium") → scoreboard (hidden)
```

Tie at step 5: TV holds at current `podium_state` with amber "Tie — Stand by..." until admin clicks "Advance Past Tie".

## Auth

Single `ADMIN_PASSWORD` env var. Session stored as encrypted cookie via `iron-session`. 24-hour TTL. Multiple concurrent sessions are supported (no invalidation). To rotate: update env var in Vercel, redeploy. Existing sessions stay valid until natural expiry.

## Deployment (Phase 6)

1. Install Vercel CLI: `npm i -g vercel`
2. `vercel link` — connect to Vercel project
3. In Vercel Dashboard: Settings → Storage → Add → Postgres → Create
4. Copy `DATABASE_URL` connection string to Vercel env vars
5. Add `ADMIN_PASSWORD` and `SESSION_SECRET` to Vercel env vars
6. Push to `main` → auto-deploy via GitHub integration
7. Run migrations: `npx drizzle-kit migrate` (with production DATABASE_URL)
8. Run seed: `npx tsx scripts/seed.ts` (with production DATABASE_URL)

## Year Lifecycle

1. Admin creates year in Setup Mode → `is_active = true`, `is_locked = false`
2. Event runs → scores entered, games marked complete
3. "Finish Games" clicked → `is_locked = true`
4. Podium reveal sequence → `display_mode` transitions through states
5. "Show Final Results" → `display_mode = 'final_results'`, `/final-results` public URL active
6. Year stays locked forever — read-only in history

## Test Years

Use year number 9999 to avoid collision with real event year (e.g., 2026). Test years:
- Show amber "⚠️ TEST" badge everywhere in admin
- Are excluded from `/history` public view
- Can be fully deleted (cascading) via Setup Mode
- Have reset controls in Live Mode (clear scores, clear votes, unlock year)
- Do NOT affect the game library (it's a shared global)

## Common Gotchas

- **Score entry is admin-only** — there is no public score entry interface
- **active_game_id must be set atomically** — when setting game X active, clear any existing active game in the same transaction
- **Costume Contest raw score** in Final Results shows vote-point total (e.g., 37), not placement points
- **2-round provisional state**: if round 1 exists but round 2 doesn't for a 2-round game, show "Provisional Rankings" in the right panel and do NOT count toward overall leaderboard until game is marked complete
- **Teams cannot be deleted if scores exist** — check before allowing delete
- **16-team cap** enforced at API level on POST /api/admin/teams
